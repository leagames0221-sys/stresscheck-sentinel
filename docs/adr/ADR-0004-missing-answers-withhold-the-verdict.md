# ADR-0004: 欠損回答は補完せず、判定を保留する

- Status: Accepted
- Date: 2026-08-21

## Context

57 項目のうち何項目かが未回答のまま提出されることは普通に起きる。この時どうするかは、
統計の問題ではなく**責任の問題**である。

参考にできる一次資料を読んだ結果:

- **K6 の公式 FAQ (Harvard / Kessler)** は、欠損値の扱いについて
  「我々は推奨を出したことがない」と明言している。保守的な選択肢として最頻値
  (`none of the time` = 0) への recode に言及するが、それは推奨ではない。
  つまり**尺度の開発者が「開発者が指図すべきことではない」と言っている領域**である。
- 一方こちらの用途は研究の記述統計ではなく、**面接指導の要否につながる法定の判定**である。
  同じ「欠損をどう扱うか」でも、間違えた時に起きることが違う。

補完した場合に何が起きるかを具体的に置くと:

- 未回答を「ちがう」相当で埋める → 高ストレスの側に寄せる項目では点が下がり、
  **本来該当した人が非該当になる**。
- 未回答を最悪値で埋める → 逆に非該当の人が該当になり、実施者の面談枠を実態と違う形で消費する。

どちらも「誰かが埋めた値」で人の扱いが変わる。しかも受検者にはその事実が見えない。

## Decision

**欠損があれば、判定を確定させない。補完しない。**

- `score()` は `missing` (欠損項目番号のタプル) と `valid: bool` を返す。
  `missing` が非空なら `valid=False`、`high_stress=False`、`rule_hit="none"`。
- `high_stress=False` は「非該当」ではなく「**判定していない**」を意味する。
  この区別が消えないよう、`valid` を同じ戻り値に同居させ、UI と CLI は
  `valid=False` の時に判定結果ではなく「未回答があるため判定できない」旨と該当項目番号を出す。
- 欠損の扱いは**採点の内部ではなく境界**の問題なので、閾値 CSV でも設定にもしない。
  設定可能にすると「補完する設定」が存在してしまう。

## Alternatives considered

| 代替 | trade-off |
|---|---|
| **最頻値 (`none of the time` 相当) で補完** | K6 FAQ が保守的選択肢として挙げている方法で、全件が必ず判定できる。だが本用途では「保守的」の向きが逆になる: 研究では偏りを小さくする方が保守的だが、法定判定では**該当を見落とす方が重い**。しかもどちらの向きに偏るかは項目 (逆転項目かどうか) に依存し、一律には言えない。 |
| **多重代入 (MI)** | 統計的には最も筋が良い。だが (1) 1 人分の判定に確率的手法を入れると、同じ回答が実行のたびに違う判定になり得る = ADR-0002/0006 で守っている決定論性を壊す、(2) 依存が増える、(3) 「あなたが未回答だった 3 項目は統計的にこう推定しました」を受検者に説明できない。 |
| **欠損が n 項目以下なら判定する (閾値方式)** | 実務的で、多くの調査票がやっている。しかしその n の根拠を厚生労働省の資料から示せなかった。**根拠のない数値を法定判定に入れないという方針** (ADR-0001) にそのまま反する。n の根拠が一次資料から得られたら、この ADR を改訂して採用してよい。 |
| **欠損項目を 0 点として合計する** | 実装が一番簡単。実質「最小値で補完」であり、補完していないふりをした補完なので不採用。 |

## Consequences

- **良い**: 「判定できなかった」が出力に現れる。埋めた値のせいで人の扱いが変わることがない。
- **良い**: 実装が純関数のままで、同じ入力に対して常に同じ結果になる。
- **悪い**: 受検者に**再回答を求める運用**が要る。1 項目の未回答でも判定は出ない。
  これは意図した不便であって、緩めるなら根拠 (上記の n) を先に用意する。
- **悪い**: 集団分析では、欠損を含む個票を除外して集計することになる
  (`GroupResult.n_excluded_incomplete` として除外数を返し、隠さない)。
  除外が偏れば集団の像も偏るので、除外数を見えるようにしてある。
