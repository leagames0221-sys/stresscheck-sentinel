# ADR-0001: ひな形調査の結果を判断の基準線として固定する

- Status: Accepted
- Date: 2026-08-21

## Context

「ストレスチェック × LLM」という題材で書けるコードはいくらでもあるが、**何を自分で書き、
何を既存物から借り、何を借りてはいけないか**を先に決めないと、後の判断が全部その場の
好みになる。特にこの題材には、後から覆すと作り直しになる制約が 3 種類ある。

1. **法定基準の数値** — 逆転項目・領域合計・高ストレスの切り分けは公開されており、
   発明する余地がない。写し間違えれば全部の出力が間違う。
2. **ライセンス** — 尺度・rubric・データセットには、商用不可 (NC) や改変不可 (ND)、
   ソフトウェアへの埋め込みを明文で禁じるものが混ざっている。実装に入れてから気付くと外せない。
3. **既存 OSS の欠陥** — star 数と健全性は一致しない。読まずに依存すると欠陥ごと継承する。

そこで実装前に 1 日を使い、候補 20 件超の LICENSE 本文・README・コードを実読する調査を行った。
結果は `docs/evidence/PRIOR_ART_REPORT_2026-08-21.md` (PAR) に全文が残っている。

調査で実際に出てきたもの (抜粋):

- 採点エンジン候補 (`code4fukui/stress-check`, MIT) に**性別判定のバグ** —
  条件式が常に真になり、女性用の列が一度も使われない。読まずに依存していれば継承していた。
- `KokoroChat` は **CC BY-NC-ND 4.0** で使用不可。GitHub API の spdx 表示は `NOASSERTION` で、
  API を信じると見落とす。
- `HumanLayer` は star 11.3k だが **README 全文が廃止宣言**。
- `WHO-5` は 2024 年に WHO へ権利が移り **CC BY-NC-SA 3.0 IGO** = NC + 継承。採用すると
  リポジトリ全体のライセンス方針が汚染される。
- `ISO 45003` は有償 (CHF155) かつ利用許諾がソフトウェアへの埋め込みと AI 利用を**明文で禁止**。

## Decision

**PAR を、以降のすべての設計判断が参照する基準線として固定する。**

- 要件 (`docs/spec/requirements.md`) の各行は PAR の該当節に接地させ、接地できない要件は書かない。
- 以降の ADR は「PAR のどの調査結果に基づくか」を Context に明示する。
- 採用したひな形は **依存にせず、読んで自作する** (decomposed prior art)。
  借りるのは設計判断であって、コードではない。
- PAR で「未確認」と書いた項目は、確認できるまで**未確認のまま扱う**。埋めない。

## Alternatives considered

| 代替 | trade-off |
|---|---|
| 調査せずに実装を始め、詰まったら調べる | 初速は速い。ただし上記のライセンス地雷 (NC/ND/埋め込み禁止) は**実装後に踏むと外せない**。作り直しの期待コストが調査 1 日を上回る。 |
| 既存 OSS を fork して改造する | 採点部分は数時間で動く。だが fork した瞬間に相手のバグ (実測で発見済) とライセンスと設計を継承する。この題材で示したいのは「出力を信用してよいかを判断する能力」であり、中身を読んでいないコードを土台にするとその主張自体が成り立たない。 |
| 調査結果を chat の散文で共有し、ファイルに残さない | 早い。しかし 3 日後には「なぜ WHO-5 を外したのか」を誰も再現できない。ADR と要件の根拠が消える。 |

## Consequences

- **良い**: 「なぜこれを使わなかったか」に毎回答えられる。ライセンス上の地雷 (NC/ND/有償/埋め込み禁止)
  は実装前に全て除外済みで、公開時に外す作業が発生しない。
- **良い**: PAR の「未確認事項」節が、そのまま README の Limitations の下書きになった。
  実際に 1 件 (判定図の回帰係数) は最後まで未取得のままで、**それを未取得として出荷している**
  (ADR-0004 / `data/sjd_coefficients.csv`)。
- **悪い**: 実装開始が 1 日遅れた。
- **悪い**: PAR は 2026-08-21 時点の観測であり、鮮度が落ちる。ライセンスや保守状況が変わったら
  PAR を改訂する必要があり、その手間はこの決定が生んだもの。
