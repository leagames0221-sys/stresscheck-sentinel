# ADR-0007: プログラム医療機器 非該当は機能設計で維持する。免責文言には頼らない

- Status: Accepted
- Date: 2026-08-21

## Context

日本では、疾病の診断・治療・予防に用いるプログラムはプログラム医療機器 (SaMD) に該当し得る。
厚生労働省の医療機器該当性ガイドラインを読んだ結果、この題材で効いてくる点は 2 つある。

1. **疾病の罹患可能性を数値等で提示する機能は、診断の側に倒れる** (別紙2)。
   「うつ病の可能性 72%」はもちろん、「メンタル不調のリスクが高い状態です」も同じ向きである。
2. **免責文言の付記は、該当性判断の根拠にならない** (注記12)。
   「本結果は診断ではありません」と書いても、機能が診断的なら判断は変わらない。

つまり **「注意書きを足す」は対策ではない**。加えて、LLM に文章を書かせる以上、
「そう書かないでください」とプロンプトに書くだけでは、書かれない保証にならない。

関連して、職場という文脈には別の線もある。EU AI Act 5(f) は職場における感情推論を原則禁止しており、
方向としては「他人が本人に感情ラベルを貼る」形を避け、「本人が自分の状態を記録・閲覧する」形に
寄せることになる。同ガイドラインの非該当類型 (自己の健康情報の閲覧・低リスク) と同じ向きである。

## Decision

**非該当を、機能の設計と機械的な検査で維持する。免責文言は補助であって根拠にしない。**

- **禁止表現 lint (`packs/samdlint`)** を全出力の経路に置く。LLM 生成文も定型文も、
  利用者に見せる前に必ず通る。辞書は `data/samd_forbidden.csv` (データであってコードではない)。
  判定は 2 種類:
  - `kind=regex` — 1 件でも一致したら block (リスク%表示など)。
  - `kind=disease` + `kind=claim` — **同一文の中に両方**が出たら block。
    疾病名だけ、主張語だけでは block しない (「うつ病について相談できる窓口」を潰さないため)。
- **出力できるものを、そもそも限定する**。この製品が出すのは
  「この調査票での合計点」と「高ストレス者に該当するか」だけで、疾病リスクの推定値は
  計算していない。**出せない値は漏れない。**
- **辞書が空なら起動しない** (`GateSetupError`)。ゲートを設定し忘れたまま「有効なつもり」で
  動く状態を作らない。
- 免責の文言はプロンプト側の必須トークン (AI であること・診断ではないこと・窓口) として
  テストで存在を強制するが、**それは lint の代わりではない**。両方ある。

## Alternatives considered

| 代替 | trade-off |
|---|---|
| **免責文言を付けて済ませる** | 実装コストがほぼゼロ。だが同ガイドライン 注記12 が明文で「根拠にならない」としている。最も安く見えて、最も成立しない選択肢。 |
| **プロンプトに「病名を書くな」と書くだけ** | 実際かなり効く。しかしモデルを替えれば効き方が変わり、検証は毎回やり直しになる。**プロンプトは効果を上げる手段であって、保証を与える手段ではない。** 本実装ではプロンプトにも書いたうえで、保証は lint 側に置いた。 |
| **疾病リスク推定を実装し、実施者にだけ見せる** | 実施者向けなら医学的判断の補助として価値がある、という筋はある。だが (1) 推定の根拠となる係数を一次資料から得られていない (ADR-0004 と同じ理由で発明しない)、(2) 該当性の線に自分から近づく設計になる。恒久的に out of scope とし、要件に明記した。 |
| **禁止語をコードに定数として持つ** | 実装は単純。だが事業場ごとに追加したい語があり、そのたびにコード変更と再デプロイになる。データ (CSV) に出し、**辞書は差し替え可能・判定ロジックは差し替え不可**という線を引いた。 |
| **lint を LLM に判定させる** | 言い換えや婉曲表現に強い。だが ADR-0006 と同じ理由 (非決定性・安全軸での judge の弱さ) で不採用。**言い換えへの弱さは辞書保守で埋める負債として引き受ける。** |

## Consequences

- **良い**: 「診断ではない」が、注意書きではなく検査で担保されている。
  敵対的入力セット (診断要求 6 件 / リスク% 要求 6 件) が決定論ゲートに落とされることを
  CI で毎 push 検査している。
- **良い**: 実測で、生成文 10 件すべてが lint を通過している
  (judge の合否とは無関係に、SaMD 側の線は越えていない)。
- **良い**: 危機時の固定応答自体も lint を通ることをテストしている
  (安全のための文章が安全検査に落ちる、という間抜けな失敗を潰してある)。
- **悪い**: 辞書ベースなので、言い換え・婉曲・新しい語には弱い。網羅性の主張はしていない。
  検知できるのは辞書に書いた範囲だけで、それは README の Limitations に書いてある。
- **悪い**: 同一文に疾病名と主張語が同居したら block する規則は、正当な文
  (「うつ病の診断は医師が行います」等) も止め得る。過剰検知の側に倒すという選択の結果で、
  止まった文は実施者の画面に理由 (どの id に当たったか) 付きで出る。
- **悪い**: この判断は 2026-08-21 時点のガイドライン読解に基づく。**法務の確認を経ていない。**
  実運用に載せるなら、機能単位の該当性判定を改めて通す必要がある。
