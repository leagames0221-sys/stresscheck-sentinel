# stresscheck-sentinel — Requirements (EARS)

> Spec-Driven stage 2 / 起草 2026-08-21 / 根拠は全て `docs/evidence/PRIOR_ART_REPORT_2026-08-21.md` (以下 PAR) に接地
> mission: 法定ストレスチェックの決定論コアの上に AI ガバナンス層 (Evals + HITL + 判断境界) を実装し、「何を作るか定義し、AI にどう指示し、出力が正しいかを判断する」能力を実物で示す。

## R1 決定論採点コア (LLM ゼロ・外部通信ゼロ)

- **R1-1** WHEN 57項目の回答 (各1-4、完全回答) が与えられた時、システムは逆転項目 (領域A 1-7,11-13,15 / 領域B 1-3) を逆転換算した上で領域A/B/C合計を算出し、単純合計法 (㋐B≥77 または ㋑A+C≥76かつB≥63) で高ストレス判定を返す SHALL。[PAR §決定論コア]
- **R1-2** WHEN 23項目版の回答が与えられた時、同様に ㋐B≥31 / ㋑A+C≥39かつB≥23 で判定する SHALL。
- **R1-3** 判定閾値・逆転項目・計算式は CSV データとして外出しし、コードに数値を埋め込まない SHALL (code4fukui 方式の継承+改良)。[PAR §採用ひな形]
- **R1-4** WHEN 回答に欠損が含まれる時、システムは判定を確定させず「欠損あり・要再回答」として保留する SHALL (欠損補完はしない。K6 公式 FAQ「開発者が欠損処理を指図すべきでない」→ 当ツールは法定判定であるため保守側=保留を採用、ADR に固定)。[PAR §user提供追加資料1]
- **R1-5** 採点・判定は pure function であり、LLM・ネットワーク・乱数を一切使用しない SHALL。
- **R1-6** WHEN 高ストレス判定基準を事業場がカスタマイズする時 (指針: 実施者意見+衛生委員会で事業者決定)、閾値 CSV の差し替えのみで反映できる SHALL。

## R2 集団分析 (仕事のストレス判定図)

- **R2-1** WHEN 10人以上の集団の回答群が与えられた時、12項目 (量的負担/コントロール/上司支援/同僚支援)・男女別の判定図に基づき総合健康リスク = (A)×(B)/100 を算出する SHALL。[PAR §決定論コア]
  - 実装現況 (2026-08-21): 4 尺度平均・除外数・判定図の性別選択までは決定論で算出するが、健康リスク回帰係数 (A/B) の一次資料が未取得のため `group_analysis` は `risk_a`/`risk_b`/`total_risk` を `None`、`coefficients_verified=False` で返す (`data/sjd_coefficients.csv` が空)。「根拠のない数値を法定判定に入れない」(ADR-0001) を型で表現したもので、係数 CSV を補充すれば skip 中の `tests/test_group.py` が自動的に走る。api_contract.md の `GroupResult` 改訂注記と整合。
- **R2-2** IF 集団人数が10人未満なら、システムは集団分析出力を拒否し理由 (個人特定リスク・安衛則52条の14系) を表示する SHALL。
- **R2-3** 集団分析出力は個人を識別できない集計値のみで構成する SHALL (2027-04施行の改正を先取り)。

## R3 境界ゲート (本ツールの中核価値)

- **R3-G1 実施者署名ゲート**: WHILE 実施者 (医師等) の確認署名レコードが存在しない間、高ストレス判定結果は下流処理 (本人通知の確定・面接指導勧奨) へ流れない SHALL。署名レコードは (対象データhash, 実施者ID, 判定, 日時) を持ち独立監査ログに追記される SHALL。[根拠=指針7-(2)「確認しなければならない」/ MS AgentFramework ADR-0006]
- **R3-G2 SaMD 禁止表現 lint**: WHEN いかなる出力テキスト (LLM生成含む) にも疾病名の可能性表示・リスク%表示・診断的表現 (禁止語辞書で定義) が含まれる時、システムはその出力を block し記録する SHALL。免責文言の付与は代替にならない (医療機器該当性ガイドライン 注記12)。[PAR §規制・安全 2]
- **R3-G3 危機エスカレーション**: WHEN 自由記述入力に危機シグナル (段階判定木: 希死念慮の探索→意図→計画→準備、PsyGUARD 写像) を検知した時、システムは LLM 生成を bypass し、決定論の固定応答 (「まもろうよこころ」掲載の相談窓口提示) を返す SHALL。判定は決定論分類が先行し、LLM に安全判定を委ねない SHALL。[PAR §規制・安全 5,6]
- **R3-G4** ゲート設定が空・不正 (禁止語辞書ゼロ件等) の場合、システムは起動時にエラーで停止する SHALL (ゲートの黙殺無効化を防ぐ。LangChain v1 middleware の設計判断を継承)。[PAR §採用ひな形 HITL]
- **R3-G5** 全機能は「本人が自分の状態を記録・閲覧する」形で提供し、第三者への感情推論ラベル付与を行わない SHALL (EU AI Act 5(f) + SaMD 非該当類型(3) の同方向設計)。

## R4 LLM 任意層 (Ollama・ローカル完結)

- **R4-1** LLM の用途はセルフケア助言文面の生成と結果の平易な言い換えに限定する SHALL (指針の「結果通知に含めることが望ましい」事項に接地)。判定・採点・危機対応には使用しない SHALL。
- **R4-2** WHERE LLM (Ollama) が利用不可の環境では、全機能が定型文フォールバックで動作する SHALL (プロジェクト制約「ローカル LLM 優先」= 決定論 core + LLM 任意層)。
- **R4-3** 全プロンプトは `prompts.yaml` に外出しし、git で版管理し、必須トークン (窓口情報・AI であることの開示・非診断の明示) の存在をユニットテストで検査する SHALL。[Anthropic AUP 開示要件 / APA advisory]
- **R4-4** LLM 出力はユーザー提示前に R3-G2 lint を必ず通過する SHALL。

## R5 Evals (求人票中核要件の実証)

- **R5-1** ゴールドセット (採点コア: 境界値ケース網羅 / LLM層: 入力→期待特性) を CSV で保持し、promptfoo で決定論 assertion + llm-rubric (Ollama judge) を同一 YAML で実行できる SHALL。
- **R5-2** 安全性軸の評価は日本版 VERA-MH (5次元 rubric + ペルソナ日本語化 + 窓口差し替え) で行い、非対称スコア `(50+%BP/2)×(1−%HPH/100)²` を採用する SHALL。[PAR §採用ひな形 危機Evals]
- **R5-3** LLM-judge は 2 モデル以上で走らせ一致度 (IRR) を報告する SHALL。安全性軸の合否判定を LLM-judge 単独に委ねない SHALL (MentalAlign-70k 実測根拠)。
- **R5-4** Evals は回帰スイートとして CI (GHA) で毎 push 実行され、敵対的テストセット (境界を越えさせる入力) を含む SHALL。[CounselBench-Adv 方式]

## R6 HITL (実施者レビューフロー)

- **R6-1** 実施者レビューは 4 決定型 `approve / edit / reject / respond` を持つ SHALL (respond = AI 出力を使わず実施者所見をそのまま返す経路)。[LangChain v1 HumanInTheLoopMiddleware 写像]
- **R6-2** 中断・再開は永続化され (SQLite)、再開時の二重実行が起きない設計とする SHALL (副作用は署名記録後)。
- **R6-3** 人間による上書き (edit/reject/respond) は全件記録され、オーバーライド率を KPI として集計表示できる SHALL。[NIST AI 600-1 MS-4.2-004]
- **R6-4** LLM 生成文のサンプリング監査キュー (代表サンプル抽出) を持つ SHALL。[APA advisory「継続的人間監査」]

## R7 プライバシー・セキュリティ

- **R7-1** 氏名・メール・社員番号等の個人情報を一切保存しない SHALL。受検者はハッシュ化トークンで管理する (stresscheck-r8 の token-only スキーマ写像)。[PAR §採用ひな形]
- **R7-2** 全データはローカル SQLite。外部通信は Ollama (localhost) のみ SHALL。Evals 実行時もクラウド送信ゼロ SHALL。
- **R7-3** プロジェクト制約「セキュリティ第一」の標準セット (gitleaks / pre-commit / private_path_check / GitHub Actions) を初回 commit から適用する SHALL。

## Out of scope (v1 で作らない)

- 面接指導の実施・記録管理 (実施者の領域)
- 80項目版 (v2 候補。厚労省プログラム非対応の差別化点として README に明記のみ)
- 労基署報告様式の出力 / 多言語 UI (調査票 10 言語の存在は README で言及のみ)
- 疾病リスクの予測・表示 (恒久 out of scope = R3-G2 で機械的に禁止)
